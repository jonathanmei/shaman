Carry dense curvature past ADMM—or let KD reshape the binaries?

A deliberately compact plan to locate where the dense NKP–Shampoo advantage is lost: in block reconstruction, in global distillation, or at the transition between continuous latent and hardened binary factors.

NanoQuant · Qwen3 · two-scale path · 5 September 2026

Decision summary

Low code difficulty

Mahalanobis block loss

Replace the feature-diagonal weighted MSE with a dense quadratic form using the shrunk o_cov from mlp.down_proj. The necessary matrix already exists.

Engineering risk is low-to-moderate; runtime overhead is moderate because each loss evaluation adds a hidden-size square matrix multiply.

Moderate difficulty

Scale + latent KD

The optimizer change is small, but binary/latent mode transitions must be made explicit. The present scale-only path also needs a correctness control before its result can be trusted.

Expect changes to parameter selection, STE state, final hardening, cache keys, checkpoint restore, and logging.

1. Dense curvature during block tuning

For a token-level block-output error E with shape [tokens, hidden], use the output-side factor from the block’s mlp.down_proj:

L_diag = Σₜ Σⱼ E[t,j]² · diag(L)[j] L_dense = Σₜ E[t,:] · L · E[t,:]ᵀ

This is the correct reuse of the NKP factors at block output. The input-side factor R should not be applied again: the observed block errors already integrate over the sampled input activations. For Qwen-style residual blocks, the down-projection output is added directly to the residual stream, making its output-side gradient factor the natural available proxy.

Implementation outline

  1. Add a block-loss mode such as block_loss = diag | mahalanobis and include it in block cache keys.
  2. Before factorization begins, retain mlp.down_proj.o_cov in a local block-level variable. Individual layer factors are currently deleted after ADMM to release memory.
  3. Implement the dense loss in fp32 as ((E @ L) * E).sum(). Symmetrize once, outside the training loop.
  4. Use the raw shrunk factor, not its unit-diagonal correlation form. Its diagonal then exactly recovers the existing weighted-MSE convention, preserving trace and approximate learning-rate scale.
  5. Use the same selected loss for both tune_nonfact and tune_fact; a mixed variant can wait unless the full change fails.
Cost caveat. The dense loss is O(tokens × hidden²) per optimization example and adds a similarly sized backward operation. It should be manageable for a diagnostic 0.6B/1.7B run, but benchmark one block before launching the full 4B matrix. A truncated eigenspace is the fallback if overhead is excessive.

2. Scale + latent global KD

Adding latent parameters to the optimizer is straightforward, but the forward mode requires care. After block tuning, finalize() retains latent parameters while creating hardened U/V. Global KD then sets do_train = True; this selects U_latent/V_latent. Because _binarized remains true, the current “scale-only” KD forward uses the continuous latents rather than STE binaries. After KD it switches back to hardened U/V.

Required control: first define a corrected scale-only mode whose forward always uses hardened U/V. Otherwise the scale-only versus scale+latent comparison changes two things at once and scales are optimized against a different model than the one evaluated.

Give latents their own learning rate—initially the existing factor binary LR or a conservative 1e-6—and keep scale LR at 1e-6. Add KD mode and latent LR to KD_FIELDS so incompatible checkpoints cannot collide. Checkpoint both parameter groups plus the mode state, and always evaluate the hardened model.

Metrics to add

At each block boundary

  • Held-out WikiText-2 PPL, as today.
  • Calibration diagonal block loss and dense Mahalanobis block loss, logged together regardless of optimized mode.
  • Optional small held-out reconstruction set with both losses to expose calibration overfitting.
  • Wall time and peak allocated/reserved CUDA memory per block.

At each layer transition

  • Actual deployed two-scale Euclidean weight error—not only continuous W_final error.
  • Actual deployed Mahalanobis weight error using the same L/R.
  • Both errors after ADMM initialization and after factor tuning/hardening.
  • Dense-versus-diagonal loss ratio and optimization time.

At every KD epoch

  • Training KL and calibration-token PPL.
  • Held-out PPL after hardening; select best epoch by this metric as well as report last epoch.
  • STE-forward versus hardened-forward KL/PPL gap before the epoch, after the update, and after finalization.
  • Scale relative drift and per-group gradient norms.

Latent-specific

  • Cumulative and per-epoch bit-flip fraction for U and V, overall and by layer type.
  • Latent sign margin: median |latent| and fraction below thresholds such as 0.01 and 0.1.
  • Number of layers with zero flips, to detect an ineffective latent LR.
  • Final PPL change per million flipped bits as a coarse efficiency measure.

Execution order and stopping rules

01

Correct the control

Implement explicit KD modes and compare current behavior, corrected hardened scale-only, and no KD from the same cached pre-KD model. Stop and reassess if corrected scale-only alone removes the 1.7B reversal.

02

Benchmark one block

Implement dense block loss and measure overhead plus both reconstruction metrics on an early and late block. Use full dense loss if overhead is acceptable; otherwise retain the top eigenspace explaining roughly 95% of trace.

03

Run the 2 × 2 matrix at 0.6B

Advance only variants that improve pre-KD PPL or final held-out PPL without a large hardening gap. Zero-shot evaluation is unnecessary at this screening stage.

04

Confirm at 1.7B

Run the corrected baseline and the best one or two experimental arms. Only then spend on extra seeds or 4B.
